# 09 · 事件驱动机制

> ApplicationEvent + @TransactionalEventListener —— 解耦业务逻辑的利器。

## 概述

Spring 的事件机制是框架内部实现模块解耦的核心手段。从简单的 `ApplicationEvent` 到事务感知的 `@TransactionalEventListener`，本 Demo 展示如何利用事件驱动模式降低模块耦合。

## 核心概念

### 事件驱动模型

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│  Publisher   │────▶│   EventBus   │────▶│  Listener A  │
│  (发布者)    │     │  (Spring     │     │  (监听器A)   │
└──────────────┘     │   Context)   │     └──────────────┘
                     │              │────▶┌──────────────┐
                     │              │────▶│  Listener B  │
                     │              │     │  (监听器B)   │
                     └──────────────┘     └──────────────┘
```

### 事件生命周期

| 阶段 | 说明 |
|------|------|
| 发布 | `ApplicationEventPublisher.publishEvent()` |
| 同步分发 | `@EventListener` 在发布线程同步执行 |
| 异步分发 | `@Async` + `@EventListener` 在独立线程执行 |
| 事务感知 | `@TransactionalEventListener` 在事务提交/回滚后执行 |

## 代码走读

### 1. 定义事件

```java
// demo08/event/event/UserRegisteredEvent.java
public class UserRegisteredEvent extends ApplicationEvent {

    private final User user;
    private final LocalDateTime registeredAt;

    public UserRegisteredEvent(Object source, User user) {
        super(source);
        this.user = user;
        this.registeredAt = LocalDateTime.now();
    }

    public User getUser() { return user; }
    public LocalDateTime getRegisteredAt() { return registeredAt; }
}

// 更简洁的 Record 形式（Spring Boot 4.x 推荐）
public record OrderCreatedEvent(Order order, LocalDateTime createdAt) {}
```

### 2. 发布事件

```java
// demo08/event/publisher/EventPublisherService.java
@Service
public class EventPublisherService {

    private final ApplicationEventPublisher eventPublisher;

    public EventPublisherService(ApplicationEventPublisher eventPublisher) {
        this.eventPublisher = eventPublisher;
    }

    @Transactional
    public void registerUser(UserRegistrationRequest request) {
        // 1. 保存用户
        User user = userRepository.save(new User(request));

        // 2. 发布事件（多个监听器会收到）
        eventPublisher.publishEvent(new UserRegisteredEvent(this, user));

        // 注意：此时事务尚未提交！
        // @TransactionalEventListener 会在事务提交后才触发
    }
}
```

### 3. 同步事件监听

```java
// demo08/event/listener/NotificationListener.java
@Component
public class NotificationListener {

    // 发送欢迎邮件
    @EventListener
    public void onUserRegistered(UserRegisteredEvent event) {
        User user = event.getUser();
        log.info("Sending welcome email to: {}", user.getEmail());
        emailService.sendWelcomeEmail(user);
    }

    // 条件过滤
    @EventListener(condition = "#event.user.department == 'VIP'")
    public void onVipRegistered(UserRegisteredEvent event) {
        log.info("VIP user registered, sending gift: {}", event.getUser().getName());
    }
}
```

### 4. 异步事件监听

```java
@Component
public class AsyncEventListener {

    @Async  // 异步执行，不阻塞发布线程
    @EventListener
    public void onUserRegistered(UserRegisteredEvent event) {
        // 耗时操作（如调用外部 API）不会阻塞主流程
        log.info("Async processing for user: {}", event.getUser().getName());
        analyticsService.trackRegistration(event.getUser());
    }
}
```

### 5. 事务感知事件监听

```java
@Component
public class TransactionalEventListener {

    // 事务成功提交后才执行
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)
    public void onUserRegisteredAfterCommit(UserRegisteredEvent event) {
        // 此时事务已提交，用户数据已持久化
        // 可以安全地查询数据库
        log.info("User {} committed to database", event.getUser().getName());
    }

    // 事务回滚后执行
    @TransactionalEventListener(phase = TransactionPhase.AFTER_ROLLBACK)
    public void onUserRegisteredRollback(UserRegisteredEvent event) {
        log.warn("User registration rolled back: {}", event.getUser().getName());
        cleanupService.cleanupResources(event.getUser());
    }

    // 事务完成后执行（无论成功或回滚）
    @TransactionalEventListener(phase = TransactionPhase.AFTER_COMPLETION)
    public void onUserRegisteredCompletion(UserRegisteredEvent event) {
        log.info("User registration completed");
    }
}
```

### 6. 自定义事件（使用 Record）

```java
// 使用 Record 简化事件定义
public record PaymentCompletedEvent(
    String transactionId,
    BigDecimal amount,
    String currency,
    LocalDateTime completedAt
) {}

// 发布
eventPublisher.publishEvent(new PaymentCompletedEvent(txId, amount, "CNY", now));

// 监听
@EventListener
public void onPaymentCompleted(PaymentCompletedEvent event) {
    log.info("Payment {} completed: {} {}", event.transactionId(), event.amount(), event.currency());
}
```

## 注解与 API 参考

| 注解 / API | 说明 |
|-----------|------|
| `ApplicationEvent` | 事件基类 |
| `ApplicationEventPublisher` | 事件发布器接口 |
| `@EventListener` | 标注事件监听方法 |
| `@EventListener(condition = "...")` | 条件过滤的事件监听 |
| `@TransactionalEventListener` | 事务感知的事件监听 |
| `TransactionPhase.AFTER_COMMIT` | 事务提交后触发 |
| `TransactionPhase.AFTER_ROLLBACK` | 事务回滚后触发 |
| `TransactionPhase.AFTER_COMPLETION` | 事务完成后触发（无论成功/失败） |
| `@Async` | 异步执行事件监听 |
| `@Order` | 控制监听器执行顺序 |

## 面试考点

::: warning 高频面试题
1. **@EventListener 和 @TransactionalEventListener 的区别？**
   - `@EventListener`：事件发布时立即执行（事务未提交）
   - `@TransactionalEventListener`：事务提交/回滚后才执行
   - 使用场景：发送通知用 `@EventListener`，需要确保数据已持久化用 `@TransactionalEventListener`

2. **事件是同步还是异步的？**
   - 默认同步：在发布线程执行
   - `@Async` + `@EventListener`：异步执行
   - Spring Boot 4.1 启用虚拟线程后，异步事件使用虚拟线程

3. **如何处理事件监听异常？**
   - 同步监听器异常会传播到发布者，可能导致事务回滚
   - 使用 try-catch 在监听器内部处理
   - 或使用 `@Async` 异步隔离
:::

## 常见陷阱

::: danger 陷阱 1：@EventListener 中查询未提交数据
`@EventListener` 在事务提交前执行，此时查询数据库可能查不到刚插入的数据。应该用 `@TransactionalEventListener(phase = AFTER_COMMIT)`。
:::

::: danger 陷阱 2：同步监听器阻塞主流程
耗时操作（发邮件、调用外部 API）放在同步 `@EventListener` 中会阻塞主请求。应使用 `@Async` 或消息队列。
:::

::: danger 陷阱 3：事件丢失
Spring 事件是内存级别的，进程崩溃则丢失。重要业务事件应使用持久化消息（数据库 + 消息队列）。
:::
