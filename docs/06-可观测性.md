# 06 · 可观测性 Observability

> Micrometer + OpenTelemetry —— 指标、追踪、日志三位一体。

## 概述

可观测性（Observability）是现代分布式系统的基础能力。本 Demo 演示如何通过 **Micrometer**（指标门面）+ **Prometheus**（指标存储）+ **OpenTelemetry**（分布式追踪）构建完整的可观测性体系。

## 核心概念

### 可观测性三大支柱


### Micrometer 核心概念

| 指标类型 | 说明 | 典型场景 |
|---------|------|---------|
| `Counter` | 只增不减的计数器 | 请求总数、错误总数 |
| `Gauge` | 可增可减的度量 | 活跃连接数、队列深度 |
| `Timer` | 耗时分布统计 | 请求处理时间、数据库查询耗时 |
| `Summary` | 值分布统计 | 响应体大小 |
| `LongTaskTimer` | 长时间任务耗时 | 批量导入、定时任务 |

## 代码走读

### 1. 依赖配置

```xml
<!-- Micrometer Prometheus 注册表 -->
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
</dependency>
```

### 2. Actuator 配置

```yaml
# application.yml
management:
  endpoints:
    web:
      exposure:
        include: "*"
  endpoint:
    health:
      show-details: always
  metrics:
    tags:
      application: ${spring.application.name}  # 全局标签
```

### 3. 自定义指标服务

```java
// demo05/observability/service/MetricsService.java
@Service
public class MetricsService {

    private final Counter requestCounter;
    private final Timer processingTimer;
    private final MeterRegistry registry;

    public MetricsService(MeterRegistry registry) {
        this.registry = registry;

        // Counter: 统计 API 调用次数
        this.requestCounter = Counter.builder("api.requests.total")
                .description("Total API requests")
                .tag("type", "demo05")
                .register(registry);

        // Timer: 统计处理耗时
        this.processingTimer = Timer.builder("api.processing.time")
                .description("API processing time")
                .tag("type", "demo05")
                .register(registry);
    }

    public void processRequest(String operation) {
        requestCounter.increment();

        processingTimer.record(() -> {
            // 业务逻辑
            simulateWork();
        });
    }

    public Map<String, Object> getMetrics() {
        return Map.of(
            "totalRequests", requestCounter.count(),
            "avgProcessingTime_ms", processingTimer.mean(java.util.concurrent.TimeUnit.MILLISECONDS),
            "maxProcessingTime_ms", processingTimer.max(java.util.concurrent.TimeUnit.MILLISECONDS)
        );
    }

    private void simulateWork() {
        try {
            Thread.sleep(ThreadLocalRandom.current().nextInt(50, 200));
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}
```

### 4. 使用 @Timed 注解

```java
// demo05/observability/controller/ObservabilityController.java
@RestController
@RequestMapping("/demo05")
public class ObservabilityController {

    private final MetricsService metricsService;

    @GetMapping("/process")
    @Timed(value = "demo05.process.time", description = "Time to process demo05 request")
    public Map<String, Object> process() {
        metricsService.processRequest("demo05");
        return metricsService.getMetrics();
    }

    @GetMapping("/metrics")
    public Map<String, Object> customMetrics() {
        return metricsService.getMetrics();
    }
}
```

### 5. 自定义 Gauge

```java
// 在配置中注册 Gauge
@Configuration
public class MetricsConfig {

    @Bean
    public Gauge activeUsersGauge(MeterRegistry registry, UserSessionManager sessionManager) {
        return Gauge.builder("active.users", sessionManager, UserSessionManager::getActiveCount)
                .description("Number of active users")
                .register(registry);
    }
}
```

## 注解与 API 参考

| 注解 / API | 说明 |
|-----------|------|
| `@Timed` | 方法执行耗时统计（需 AOP） |
| `@Counted` | 方法调用次数统计 |
| `Counter` | 计数器（只增不减） |
| `Timer` | 计时器（耗时分布） |
| `Gauge` | 仪表盘（可增可减） |
| `MeterRegistry` | 指标注册中心 |
| `Tag` | 指标标签（维度） |

## 面试考点

::: warning 高频面试题
1. **Micrometer 和 Prometheus 是什么关系？**
   - Micrometer 是指标采集的"门面"（facade），类似 SLF4J
   - Prometheus 是指标存储和查询的"实现"之一
   - Micrometer 支持多种后端：Prometheus、Datadog、InfluxDB 等

2. **Timer 和 Counter 有什么区别？**
   - Counter 只增不减，适合统计总量（请求数、错误数）
   - Timer 记录耗时分布，提供 count、sum、mean、max、percentiles
   - Timer 内部包含 Counter（调用次数）

3. **@Timed 注解需要哪些前提？**
   - 需要 `spring-boot-starter-aop` 依赖
   - 需要 `@EnableAspectJAutoProxy`
   - Spring Boot Actuator 自动配置 `TimedAspect`
:::

## 常见陷阱

::: danger 陷阱 1：指标爆炸
不要为每个用户/请求创建独立的 Tag 值，会导致指标数量爆炸。应该使用 Histogram 或 Summary 代替。
:::

::: danger 陷阱 2：Timer 未记录异常
默认情况下，Timer 只记录成功执行。异常路径需要显式处理：
```java
timer.record(() -> {
    try { doWork(); }
    catch (Exception e) { errorCounter.increment(); throw e; }
});
```
:::

::: danger 陷阱 3：Actuator 端点暴露安全问题
`include: "*"` 会暴露所有端点，生产环境应只暴露需要的：
```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,prometheus,info
```
:::
